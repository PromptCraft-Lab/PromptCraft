# Issue Workflow

이 문서는 이슈를 작성하고 분류할 때 확인할 항목을 정리한다.

## Checks

- 이슈가 하나의 목적만 다루는지 확인한다.
- 버그, 기능, 작업 중 무엇인지 먼저 고른다.
- 제목이 너무 길지 않은지 확인한다.
- 재현 단계나 기대 결과가 필요한 이슈인지 본다.
- 관련 문서와 검증 방법을 함께 적는다.

## Template Choice

- 버그는 `bug_report.md`를 쓴다.
- 새 기능이나 개선은 `feature_request.md`를 쓴다.
- 문서, 운영, 유지보수 작업은 `task_request.md`를 쓴다.

## Submission Rule

- 정보가 비어 있으면 먼저 채운다.
- 확인 방법이 없으면 이슈를 제출하지 않는다.
- 범위가 넓으면 먼저 쪼갠다.
